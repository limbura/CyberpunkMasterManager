# CYBERWALL — мастерская, v2.1

Консольная программа для аккаунтов, карт и прав доступа к замкам.
Главный файл теперь **cyberwall_master.py**. Внутренние модули находятся в `modules`,
тесты — в `tests`, описание протокола считывателя — в `docs`.

## Обновление с 2.0 / 2.0.1

1. Закройте старую программу и распакуйте весь архив в новую папку.
2. Если меняли DEFAULT_HOST, DEFAULT_PORT, DEFAULT_USER или другие настройки,
   перенесите их из прежнего lock_manager.py в начало cyberwall_master.py.
3. Если рядом со старой программой остался pending_id_change.json, перенесите его
   в новую папку рядом с cyberwall_master.py. Подтверждение наклейки не потеряется.
4. Запускайте новый start.bat. Старые файлы lock_manager.py, card_console.py и
   windows_console.py в корне новой папки не нужны; копировать их не следует.

Зависимости по сравнению с предыдущей версией не изменились.

## Установка и запуск

Нужен Python 3.11+. В PowerShell в папке программы:

```powershell
py -m pip install -r requirements-reader.txt
py cyberwall_master.py
```

После установки зависимостей можно запускать start.bat двойным щелчком.
Не запускайте программу прямо из ZIP.

Без считывателя достаточно зависимостей из requirements.txt:

```powershell
py -m pip install -r requirements.txt
```

Считыватель и hidapi опциональны. Их отсутствие не мешает ручному поиску и изменениям БД.
USB можно подключать во время работы. Закройте nfcPro и другие программы, занимающие устройство.
При нескольких считывателях оставьте подключённым один.

## Настройки

В начале cyberwall_master.py:

- DEFAULT_HOST, DEFAULT_PORT, DEFAULT_USER — подключение по умолчанию;
- DATABASE_NAME — база (cyberwall);
- PAGE_SIZE — число строк на странице;
- READER_ENABLED — True / False: включить или полностью отключить RFID;
- WRITE_BEEP_T — длительность отдельного писка после записи (10; поле T, не миллисекунды).

Адрес, порт и пользователя MySQL также можно менять при запуске. Пароль БД вводится скрыто и не сохраняется.

## Поиск и таблицы

Поиск по имени, описанию замка, ID, card_id, части номера. Enter — показать всех;
n/p — страницы; номер строки — выбор; :b — назад; :q — выход.
Числа можно вводить с пробелами между разрядами.

Результаты имеют заголовки колонок: №, Тип, ID, lock_id, card_id, Имя / описание,
деньги, рейт, ур. деки, полиц. права. В строках — только соответствующие значения.
Для незаполненных или неприменимых полей выводится «-». Заголовки повторяются на каждой странице,
нумерация сквозная. Такой же формат используется для выбранного аккаунта и списков доступа.

Вместо ввода можно приложить карту: Enter не нужен. Это работает в общем поиске,
при выборе аккаунта для выдачи/отзыва доступа к замку и в списке найденных кандидатов.
По карте ищется точное совпадение main.card_id, не UID чипа и не main.id.
Удерживаемая карта повторно не выбирается; для повторного выбора уберите её и приложите снова.

Чтение и штатная индикация продолжаются во всех меню. Карта выбирает аккаунт только
на этапах поиска; при редактировании имени, пароля или подтверждениях она не меняет выбранный аккаунт.
Снятие карты отслеживается и во время работы с меню.
Исправленный ввод Windows из v2.0.1 сохранён: Unicode-события консоли и пакетная перерисовка.

## Меню аккаунта

| Пункт | Действие |
|---|---|
| 1 | Назначить доступ к замкам |
| 2 | Отозвать доступ к замкам |
| 3 | Обновить |
| 4 | Изменить имя |
| 5 | Изменить деньги |
| 6 | Изменить рейт |
| 7 | Изменить уровень деки |
| 8 | Изменить полицейские права |
| 9 | Посмотреть и изменить пароль |
| 10 | Изменить ID |
| 11 | Записать карту |

Деньги и рейт задаются новым итоговым балансом, а не прибавлением/списанием введённого числа.
Допустим signed INT: −2 147 483 648…2 147 483 647. Уровень деки: 0…255.
Полицейские права: 1 — назначить; «-» — снять. Снятие сохраняет **SQL NULL**, который отображается «-».
Ввод 0 или NULL также воспринимается как снятие прав и сохраняется как NULL, не 0.
Ранее сохранённые нули автоматически массово не изменяются.

Имя — непустая строка до 255 символов. Пароль — строка до 255 символов;
ведущие нули и пробелы сохраняются. Пункт 9 сначала показывает текущий пароль.
Enter / :b — назад, :empty — установить пустой пароль. :b, :q и :empty зарезервированы как команды.

Перед изменением показываются старое и новое значения и запрашивается подтверждение.
Изменение выбранного поля другим клиентом до сохранения приводит к отмене операции.
Программа не добавляет записи в logs самостоятельно; существующие триггеры БД работают как обычно.

## Смена ID

ID на наклейке — main.id. Номер в памяти карты — main.card_id.
После предупреждения и подтверждения вызывается changeId(cardId, OUT newId, OUT errCode).
При успехе выводится **ID ИЗМЕНЕН** и новый номер для наклейки.
Напишите его на наклейке и введите в подтверждение. Ошибочный ввод прямо отмечается как неправильный ID.
До верного подтверждения другие действия недоступны; :q завершает программу.

Незавершённое подтверждение сохраняется в pending_id_change.json рядом с главным файлом.
При повторном запуске с тем же подключением программа читает текущий ID и просит подтвердить наклейку;
процедура автоматически повторно не вызывается. Не удаляйте этот файл до подтверждения.
Папка программы должна разрешать запись. Используйте одну запущенную копию из этой папки.

## Запись карты и восстановление индикации

Выберите аккаунт → пункт 11 → приложите одну карту → подтвердите запись.
Сообщение «Карта приложена» больше не выводится: приглашение не выдаётся за результат проверки.
Перед записью API выполняет свежий поиск и чтение карты в новом USB-сеансе.
Если карты нет, сообщается: «Карта не обнаружена. Запись не выполнялась».
После прикладывания снова выберите пункт 11. Автоматического повторения записи нет.

В память записывается card_id выбранного аккаунта. Прежний номер заменяется;
main.card_id в БД не изменяется. Успех объявляется только после проверки обратным чтением.
При прочих сбоях результат не подтверждён: карта могла измениться, её нужно проверить чтением.
Ошибка писка после успешной проверки не отменяет подтверждённую запись.

Фоновый опрос приостанавливается исключительно на время записи и автоматически возобновляется
в finally после любого исхода, включая отсутствие карты и ошибку. Повторные прикладывания
не требуют возвращения в поиск. Следующий опрос снова отправляет команду LED для штатной индикации.
Сбой индикации больше не отключает её навсегда: выполняются повторные попытки (примерно раз в секунду).
Задержка физического USB-ответа всё ещё зависит от устройства и драйвера.

Протокол wcopy_reader v1.4.3 сохранён: MIFARE Classic, блок 1 сектора 0, ключ A FF FF FF FF FF FF,
байты 8–15 — uint64 big-endian, байты 0–7 сохраняются. Проверяются весь блок и UID.
После записи — отдельный beep с T=10; при опросе — команды LED для штатного цвета/звука,
без дополнительного beep. Прямое управление цветом не считается подтверждённым.

## База данных

Нужны SELECT на main, locks, lock_access; UPDATE колонок name, money, losa,
netrunner_lvl, police, password таблицы main; EXECUTE на setLockAccess и changeId.
Столбец police должен допускать NULL. Программа не меняет схему и права БД автоматически.
Прямой UPDATE main.id и main.card_id не используется.

setLockAccess(lock_id, card_id, grantAccess, OUT errCode): 0 — успех, 1 — аккаунт не найден,
2 — замок не найден, 3/5 — доступ уже есть, 4/6 — доступа уже нет. Транзакцией управляет клиент.
changeId(cardId, OUT newId, OUT errCode) сама управляет транзакцией: 0 — успех, 1 — аккаунт не найден.
Неопределённые результаты изменений после обрыва связи автоматически не повторяются.

## Проверки

```powershell
py -m unittest discover -s tests -v
```

40 автономных тестов: таблицы и страницы, NULL для полицейских прав, подтверждение ID,
выбор по карте, права доступа, запись card_id, отсутствие карты, восстановление индикации,
работа опроса вне поиска, клавиатура Windows, конкурентные изменения и обрывы связи.
Тесты используют имитации MySQL и USB и не меняют настоящую БД или карты.
Физический считыватель и сервер БД в среде сборки недоступны.
