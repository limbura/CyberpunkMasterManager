# wCopy: чтение, запись и отдельная индикация — 1.4.3

Для PMX-V624-C / wCopy NSR109-HIDIC V806N, USB 2518:6018, HID interface 0.
Python 3.11+, зависимость `hidapi` из requirements.txt.
MIFARE Classic: **блок 1 сектора 0**, **ключ A = FF FF FF FF FF FF**.
ID по умолчанию — **байты 8…15**, беззнаковое 64-битное число **big-endian**.

## Быстрый запуск на Windows

Распакуйте архив. Если обновляете прежнюю папку, замените файлы и сохраните `.venv`.
Закройте nfcPro и другие приложения, работающие со считывателем.
При первом запуске в новой папке:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запускайте именно Python из окружения, куда установили hidapi:

```powershell
.\.venv\Scripts\python.exe .\examples\read_example.py
.\.venv\Scripts\python.exe .\examples\write_example.py
.\.venv\Scripts\python.exe .\examples\watch_example.py
```

Запись с ID в командной строке:

```powershell
.\.venv\Scripts\python.exe .\examples\write_example.py 555
```

## Принцип: приложение решает, когда показывать свет и подавать звук

Обычные `read_card()`, `read_card_number()`, `write_card_number()` и
`watch_cards()` **не отправляют команды LED или писка**. Они всё ещё настраивают
радиополе для работы с картой; собственная индикация прошивки возможна.

Отдельные функции:

```python
from wcopy_reader import set_led, beep

set_led("red")     # маска «красный»; прямой цвет не гарантируется
set_led("green")   # маска «зелёный»; важен сам вызов после опроса
set_led("off")     # маска «выключить»; реальное выключение не подтверждено
beep()             # один сигнал, T=5 по умолчанию
beep(t=10)         # более длинный сигнал, как в примере записи
```

Вызовы открывают и закрывают HID автоматически. Каждый возвращает сырой ответ
`bytes`; ошибки передаются через `RFIDError` и его подклассы. Доступны параметры
`path` и `timeout_ms`, как у чтения, а также `initialize=False`.
После read/write дополнительный INIT не требуется. Для самостоятельного вызова
можно передать `initialize=True`; это выполняет только INIT, не поиск карты.

**Команды LED необходимо сохранять для штатной индикации при опросе.**
В аппаратных тестах NSR109-HIDIC V806N от 11.10.2026 режимы red, green и off
вели себя одинаково: без карты красный, с картой зелёный и один штатный писк.
Если после чтения не отправлять команду индикации, LED остаётся красным и
писка нет. Повторное открытие/закрытие HID и дополнительная пауза около 52 мс
не заменяют команду. Поэтому повторяйте set_led после КАЖДОГО успешного опроса
и ответа «нет карты», как в watch_example. Минимальная необходимая частота
ещё не исследована; сохраняем проверенную последовательность.

**Напрямую задать цвет или выключить LED этими функциями не удалось.**
Одиночные команды после INIT или чтения, в том же или новом HID-сеансе,
видимого переключения не дали. Команда red не заставляет LED оставаться
красным при карте, off не гарантирует выключение. Названия сохранены для
совместимости и дальнейшего исследования. Механизм влияния на штатную
индикацию пока неизвестен. Ответ 90 01 не подтверждает физический цвет.
Опыт без INIT завершился ошибкой USB и не доказывает отсутствие поддержки.

Писк подтверждён отдельно: T=1 очень короткий; T=3 длиннее; T=5 и T=10 близки
к штатному. В nfcPro найдены обычные вызовы с T=5 и отдельный с T=10.
На этих опытах изменения LED во время писка не замечены; независимость
для всех режимов не гарантируется. В watch дополнительный beep не нужен:
штатный звук уже работает благодаря командам индикации. После записи LED-команды
не дали звука; там используем отдельный beep(t=10) после обратной проверки.

Параметр `t` у `beep()` — **целое число 1..255, сырое поле T, не миллисекунды**.
По умолчанию t=5. Аппаратно проверены 1, 3, 5, 10; рост времени USB-ответа
составил примерно 10–11 мс на единицу T, но это не измерение звука.
Неверное значение (включая bool и дробное число) даёт ValueError до открытия USB.
Для больших T при необходимости увеличьте timeout_ms, например до 5000.

## Настройки в примерах

Настройки стоят в начале каждого файла:

| Пример | Настройки по умолчанию | Поведение |
|---|---|---|
| `read_example.py` | `SUCCESS_LED = "green"`, `SUCCESS_BEEP = False` | После чтения команда индикации с маской green (не гарантия цвета) |
| `write_example.py` | `SUCCESS_LED = None`, `SUCCESS_BEEP = True`, `SUCCESS_BEEP_T = 10` | После подтверждённой записи отдельный писк с T=10 |
| `watch_example.py` | `USE_LED = True`, `IDLE_LED = "red"`, `PRESENT_LED = "green"`, `EXTRA_BEEP = False` | Прежний проверенный режим с командами LED без дополнительного писка |

Для SUCCESS_LED значение None означает «не отправлять команду индикации».
Можно задать `"red"`, `"green"` или `"off"`, учитывая ограничения выше.
SUCCESS_BEEP_T в write_example определяет значение T отдельного писка.

Во всех примерах есть `--no-feedback`, отключающий команды индикации приложения.
В watch на проверенном устройстве это также лишает штатного цвета/писка при опросе.
У write_example есть `--no-beep`. У watch_example флаг `--no-beep` сохранён,
но теперь это поведение по умолчанию; `--beep` включает дополнительный импульс.
`--no-beep` не отключает самостоятельные звуки прошивки.

Сбой LED/пищалки не отменяет успешное чтение или подтверждённую запись:
пример выдаёт отдельное предупреждение. В watch после ошибки индикации её
команды отключаются до перезапуска, а события карт продолжают поступать.

## Чтение и запись в своём приложении

```python
from wcopy_reader import read_card_number, write_card_number, set_led, beep, RFIDError

number = read_card_number()
set_led("green")
```

Для записи отделяйте обработку ошибок данных от ошибок индикации:

```python
try:
    actual_id = write_card_number(555)
except RFIDError as error:
    print("Успех записи не подтверждён:", error.code, error.stage, error)
else:
    print("Записано и проверено:", actual_id)
    try:
        beep(t=10)
    except RFIDError as error:
        print("Запись успешна, но сигнал не подтверждён:", error)
```

Запись всегда сначала читает блок, сохраняет байты вне выбранного диапазона,
записывает весь 16-байтовый блок, затем выключает/включает RF-поле, снова ищет
карту, авторизуется и читает блок. Успех возвращается только при совпадении
**UID и всех 16 байт**. Блок 0 с заводским UID и блок ключей не записываются.

Функция возвращает ID из контрольного чтения. Ноль допустим. Диапазон по
умолчанию: **0…18446744073709551615**. Это двоичное число, не строка ASCII
и не MIFARE value block. Параметры формата: `offset=8, length=8, byteorder="big"`.
Они доступны у read_card_number и write_card_number. Неверные аргументы
вызывают ValueError до обращения к считывателю.

При ошибке после отправки команды записи карта уже могла измениться.
Автоматического повтора или отката нет. Проверьте ID через read_example.py.
Держите одну карту на считывателе до завершения операции.

Полные данные доступны через `card = read_card()`:
`card.uid`, `card.block` (16 байт), `card.atqa`, `card.sak`, `card.number`.
Метод `card.to_int(offset=8, length=8, byteorder="big")` задаёт формат числа.

## Наблюдение и индикация в приложении

Без индикации, только новые прочитанные карты и ошибки:

```python
from wcopy_reader import watch_cards, CardPresented

for event in watch_cards():
    if isinstance(event, CardPresented):
        print(event.number, event.uid.hex(" "))
    else:
        print(event.error.code, event.error)
```

Для приложения со штатной индикацией прошивки используйте `report_state=True`:

```python
from wcopy_reader import watch_cards, CardState, CardPresented, set_led, RFIDError

for event in watch_cards(report_state=True):
    if isinstance(event, CardState):
        try:
            set_led("green" if event.present else "red")
            # Если нужен дополнительный звук:
            # if event.is_new:
            #     beep()
        except RFIDError as error:
            print("Ошибка индикации:", error)
    elif isinstance(event, CardPresented):
        print("Новая карта:", event.number)
    else:
        print("Ошибка чтения:", event.error)
```

`CardState` выдаётся после каждого успешного чтения или ответа «нет карты».
`present` учитывает фильтр снятия, `is_new` означает новое успешное чтение,
после которого отдельно следует CardPresented с полными данными.
Пример watch_example повторяет LED на каждом таком событии, как в проверенной
версии: команды чтения и RF-поля могут менять индикацию самостоятельно.
Выбор маски команды и дополнительного звука находится в примере;
реальный цвет на проверенном устройстве выбирает прошивка по наличию карты.

Правила обнаружения не изменились:

- Тот же UID не создаёт нового CardPresented до двух последовательных
  ответов «нет карты» (removal_checks=2) или до чтения другого UID.
- Один пропуск опроса не означает снятие и не включает новый писк.
- Ошибки USB, тайм-ауты и авторизации не считаются снятием карты.
- Повторы одинаковых ошибок подряд подавляются; CardError содержит RFIDError.
- `63 00` на этапе poll трактуется как «карта не обнаружена» для этой прошивки.
  Это может быть неудачный поиск присутствующей карты. Два таких результата
  способны создать ложное повторное прикладывание — ограничение опроса.
- Изменение ID у удерживаемой карты с тем же UID не создаёт нового события.

Для совместимости сохранены `watch_cards(feedback=True, sound=False)` и
`set_reader_feedback(color, beep=False)`. При beep=True он использует T=5;
для другого T вызывайте отдельный beep(t=...). Это старый необязательный путь;
не включайте его одновременно с ручной индикацией, иначе возможны дубли.
Обычный watch_cards() по-прежнему выдаёт только CardPresented/CardError.

## Подключение и потоки

`list_readers()` возвращает ReaderInfo: path, product, manufacturer, interface.
При нескольких устройствах выберите одно и передавайте его path во все вызовы
чтения, записи и индикации. Без path требуется ровно один подходящий считыватель.
`timeout_ms=2500` ограничивает один HID-ответ, а не длительность всей операции.

Вызовы блокирующие и сериализуются внутри процесса. Чтение/запись/индикацию
в GUI выполняйте в рабочем потоке; передавайте события через очередь.
watch_cards принимает `stop=threading.Event()`: stop.set() завершает цикл
после текущей операции. `interval=0.25` — пауза после опроса/обработки события.
Другие процессы со считывателем одновременно работать не должны.

## Ошибки

Ожидаемые аппаратные ошибки наследуются от RFIDError.
Поля: code, stage, status (если имеется), response (если имеется).
Ветвите логику по классам/code, а не по тексту сообщения.

| Класс | Значение |
|---|---|
| DependencyError | Не загрузился hidapi |
| ReaderNotFoundError / MultipleReadersError | Нет считывателя / требуется выбрать один |
| ReaderOpenError / USBError | Не удалось открыть устройство / ошибка обмена |
| ReaderTimeoutError | Нет ответа в срок |
| ProtocolError / ReaderCommandError | Повреждённый ответ / ошибка команды |
| NoCardError / UnsupportedCardError | Карта не найдена / неподдерживаемый тип |
| AuthenticationError / CardReadError | Ошибка авторизации / чтения |
| CardWriteError | Команда записи вернула ошибку |
| VerificationError | После записи не подтверждены UID и весь блок |
| FeedbackError | Неожиданный ответ команды индикации |

При VerificationError исходная ошибка повторного чтения доступна через
`error.__cause__`, если она была. Сбой авторизации не доказывает неверный ключ:
причиной может быть снятие карты или плохая связь.

## Версия 1.4.2: диагностика индикации

Основа — версия 1.4.1 со структурой папок пользователя. Добавлен только
диагностический скрипт и это описание; поведение функций библиотеки и примеров
не менялось. Экспериментальные локальные правки write_example в эту сборку не входят.

Запустите кнопкой VS Code файл `tests_and_other/indication_diagnostics.py` или
из основной папки проекта:

```powershell
.\.venv\Scripts\python.exe .\tests_and_other\indication_diagnostics.py
```

Начните с пункта **1**. Скрипт ведёт по семи режимам. Перед каждым режимом
переподключите USB по инструкции, затем следуйте фазам: карта отсутствует,
приложить и держать, убрать. После опыта впишите реальные цвет и звук.
Не считайте одинаковый ответ `90 01` доказательством физического эффекта.

| Режим | Действие после каждого опроса |
|---|---|
| A | Ничего, как watch с --no-feedback |
| B | red/green по наличию карты, как штатный watch без отдельного beep |
| C | Открыть и закрыть HID, не отправляя команд |
| D | Только задержка: медианное время дополнительного действия из B |
| E | Всегда команда red |
| F | Всегда команда green |
| G | Всегда команда off |

Во всех режимах одинаковый порядок чтения и интервал 0.25 с после действий.
Две проверки отсутствия подряд снимают состояние «карта есть», как в watch.
Тайм-ауты, ошибки авторизации и другие ошибки прекращают опыт, а не трактуются
как снятие карты. Команда цвета в диагностике передаётся с сохранением сырого
ответа без предположений о его семантике. Нет автоматической записи карты.

Результаты помогают разделить причины, но один прогон не доказывает механизм
прошивки. Если эффект даёт C, важно открытие/закрытие HID. Если только D —
возможно влияние времени; медиана приближённая, нужна повторная проверка.
Если B/E/F/G работают, а A/C/D нет, влияние связано с обменом FF0040.
Если E/F/G задают реальный цвет независимо от карты — маски управления работают.
Если поведение одинаковое для разных масок и следует наличию карты — возможен
побочный эффект команды или включение автоматического режима.

Пункт **2** сравнивает одиночные команды red, green, off, red в четырёх условиях:
после USB без INIT, после INIT без чтения, после чтения в том же HID-сеансе,
после чтения в новом HID-сеансе. После каждого опыта также проверяется
прикладывание/снятие карты без дальнейших команд от программы.

Пункт **3** меняет только параметр T в команде писка: 1, 3, 5, 10.
Перед серией выполняется чтение; каждый писк отправляется в новом HID-сеансе,
как публичный beep(). Карта остаётся неподвижной. Единицы T неизвестны;
не приравнивайте число к миллисекундам. Возможное изменение LED тоже отметьте.
Тест после чтения не заменяет окончательную проверку после реальной записи.

Журнал USB-пакетов `.log` и ответы пользователя `.json` автоматически сохраняются
в `diagnostics_logs` рядом с библиотекой. Пришлите оба файла одного запуска.
Можно закончить после группы 1 и обсудить результат, остальные пункты необязательны
до анализа. Для выхода используйте q; Ctrl+C завершает скрипт с сохранением данных.
