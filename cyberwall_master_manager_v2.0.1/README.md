# CYBERWALL — мастерская: аккаунты, карты и замки (v2.0.1)

Расширенная версия вашего `lock_manager.py`. Основной файл оставлен с прежним именем.
Скрипт использует существующую базу `cyberwall`; таблицы и процедуры не создаёт и не меняет.

## Исправление v2.0.1 — задержки при вводе поиска в Windows

Заменён посимвольный ввод через `msvcrt.kbhit()/getwch()` на Unicode-события `ReadConsoleInputW`.
Пустая очередь не вызывает блокирующее чтение. Отпускания клавиш, мышь и служебные события
потребляются отдельно от текста; число событий за цикл ограничено.
Подсказка выводится один раз, а строка перерисовывается пакетно, без полного повторения на каждый символ.
Длинная строка прокручивается в пределах ширины окна. На время ввода выключен Quick Edit,
который может приостанавливать вывод при выделении текста мышью; исходный режим восстанавливается.

**Обновление с v2.0:** закройте программу, замените `card_console.py` и добавьте `windows_console.py`
из этого архива в прежнюю папку рядом с `lock_manager.py`. Сам `lock_manager.py`, настройки и
`pending_id_change.json` менять или удалять не нужно. Новые пакеты Python не требуются.

Исправленный путь ввода прошёл 32 автоматические проверки, включая имитацию событий Windows,
кириллицу, вставку 200 символов и задержку USB. На реальной Windows в среде сборки не проверялся;
точная причина задержек на конкретном компьютере пока не подтверждена.

## Установка и запуск в Windows

Нужен Python 3.11 или новее. Распакуйте **весь архив** в отдельную папку.
Откройте PowerShell в этой папке и выполните:

```powershell
py -m pip install -r requirements-reader.txt
py lock_manager.py
```

Либо после установки зависимостей запустите `start.bat` двойным щелчком.
Не запускайте программу прямо из ZIP. `card_console.py` и `wcopy_reader.py` должны лежать рядом с `lock_manager.py`.

Для работы только с клавиатурой достаточно:

```powershell
py -m pip install -r requirements.txt
py lock_manager.py
```

Отсутствие USB-считывателя или пакета hidapi не мешает ручному поиску и работе с БД.
Считыватель можно подключить позже, не перезапуская программу. После установки hidapi во время работы программу лучше перезапустить.
Закройте nfcPro и другие приложения, использующие считыватель. Поддерживается один подключённый совместимый считыватель.

## Настройки

В начале `lock_manager.py`:

- `DEFAULT_HOST = "127.0.0.1"`, `DEFAULT_PORT = 3306`, `DEFAULT_USER = "master"` — параметры подключения по умолчанию;
- `DATABASE_NAME = "cyberwall"` — имя базы;
- `PAGE_SIZE = 15` — строк на странице;
- `READER_ENABLED = True` — разрешить считыватель; `False` полностью отключает его;
- `WRITE_BEEP_T = 10` — длительность отдельного писка после успешной записи. Это поле T команды, не миллисекунды.

Адрес, порт и пользователя MySQL также можно менять при запуске. Пароль подключения вводится скрыто и не сохраняется.

## Поиск аккаунтов и замков

Можно искать по имени, описанию, ID, card_id и части номера. Enter показывает всех, `n`/`p` меняют страницы.
Номер строки выбирает результат. `:b` возвращает назад, `:q` завершает программу.
Числа можно вводить с пробелами между разрядами.

Вместо ввода поиска **просто приложите карту** — Enter нажимать не нужно. Это работает:

- в общем поиске;
- в поиске аккаунта для выдачи/отзыва доступа к выбранному замку;
- в списке найденных кандидатов в этих поисках.

По карте ищется точное совпадение `main.card_id`, а не UID чипа и не `main.id`.
Если аккаунт отсутствует, появляется сообщение, после чего можно продолжить ручной поиск.
Удерживаемая карта не выбирается повторно: для повторного сканирования уберите её и приложите снова.
В поиске только замков, вводе значений и подтверждениях чтение карты не заменяет ввод с клавиатуры.
Автоматическое чтение рассчитано на обычную консоль Windows / Windows Terminal / терминал VS Code, а не окно Debug Console или перенаправленный stdin.

В строках аккаунтов выводятся: ID, card_id, имя, **деньги**, **рейт**, **ур. деки**, **полиц. права**.
При длинных именах разверните терминал или уменьшите масштаб текста.

## Меню выбранного аккаунта

| Пункт | Действие |
|---|---|
| 1 | Назначить доступ к замку |
| 2 | Отозвать доступ к замку |
| 3 | Обновить данные |
| 4 | Изменить имя (`name`) |
| 5 | Изменить деньги (`money`) |
| 6 | Изменить рейт (`losa`) |
| 7 | Изменить уровень деки (`netrunner_lvl`) |
| 8 | Изменить полицейские права (`police`) |
| 9 | Показать и при необходимости изменить пароль (`password`) |
| 10 | Сгенерировать новый ID и подтвердить обновление наклейки |
| 11 | Записать card_id выбранного аккаунта на карту |

Для замка сохранено прежнее меню прав доступа.

Редактирование денег и рейта задаёт **новый итоговый баланс**, а не прибавляет введённое число.
Диапазон — signed INT: −2 147 483 648…2 147 483 647. Уровень деки — 0…255, полицейские права — 0 или 1.
Имя — непустая строка до 255 символов. Пароль — строка до 255 символов: ведущие нули и пробелы сохраняются.
В пункте пароля сначала виден текущий пароль. Enter / `:b` — назад; `:empty` — установить пустой пароль.
Значения `:b`, `:q`, `:empty` зарезервированы как команды в этом вводе.

Перед изменением показываются старое и новое значения и запрашивается подтверждение.
Если другой клиент успел изменить редактируемое поле, сохранение отменяется, чтобы не затереть чужое изменение.
Изменения полей выполняются через UPDATE по стабильному card_id. Автоматические записи в таблицу logs этим скриптом не добавляются; существующие триггеры БД работают как обычно.

## ID на наклейке и номер в памяти карты

Это разные значения:

- `main.id` — девятизначный номер на наклейке;
- `main.card_id` — число в памяти карты, по которому определяется аккаунт.

Пункт 10 предупреждает о необходимости обновить наклейку, затем после «да» вызывает:

```sql
CALL changeId(card_id, OUT newId, OUT errCode);
```

Программа выводит новый ID. Напишите его на наклейке, затем **введите этот ID в подтверждение**.
До подтверждения нельзя вернуться к другим действиям. Можно завершить программу через `:q`;
тогда при следующем подключении к той же БД она снова попросит подтвердить наклейку, не генерируя ID повторно.
Смена ID не меняет card_id и не требует перезаписи памяти карты.

Для восстановления после закрытия рядом со скриптом временно сохраняется `pending_id_change.json`.
Папка программы должна разрешать запись. Не удаляйте этот файл, пока не завершено подтверждение.
При обрыве связи программа не повторяет CALL: при следующем запуске читает текущий ID из БД и просит привести наклейку в соответствие с ним.
Если ID успел измениться ещё раз, подтверждать потребуется текущий номер из БД.
Запускайте одну копию программы из этой папки; напоминание сохраняется только на этом компьютере.

## Запись карты

Выберите аккаунт → пункт 11 → приложите одну карту → подтвердите «да».
Будет записан **card_id выбранного аккаунта**, даже если до этого карта принадлежала другому аккаунту.
Номер в памяти карты заменяется; таблица main и card_id аккаунта не изменяются.

Включён исходный `wcopy_reader.py` версии 1.4.3 без изменения протокола:

- MIFARE Classic, блок 1 сектора 0;
- ключ A: `FF FF FF FF FF FF`;
- байты 8–15: uint64 big-endian;
- байты 0–7 сохраняются;
- после записи проверяются весь блок и UID обратным чтением;
- после подтверждённой записи отправляется писк с T=10.

При ожидании карты повторяются команды LED, необходимые для штатной индикации прошивки;
дополнительный писк при чтении не отправляется. Прямое управление цветом этими командами не считается подтверждённым.
Сбой писка после успешной проверки не превращает успешную запись в ошибку.
При ошибке записи/проверки результат не объявляется успешным и команда автоматически не повторяется.
Опрос во время записи остановлен; USB-вызовы выполняются последовательно.

## Ожидаемые права и процедуры MySQL

Нужны:

- SELECT на `main`, `locks`, `lock_access`;
- UPDATE колонок `main.name`, `money`, `losa`, `netrunner_lvl`, `police`, `password`;
- EXECUTE на `setLockAccess` и `changeId`.

Прямое право UPDATE на `main.id` / `main.card_id` программе не требуется.
Пароль аккаунта читается только в соответствующем пункте, а не в общем поиске.

Сохранён вызов `setLockAccess(lock_id, card_id, grantAccess, OUT errCode)`.
Поддерживаются коды 0 — успех; 1 — аккаунт не найден; 2 — замок не найден;
3/5 — доступ уже есть; 4/6 — доступа уже нет. Транзакцией setLockAccess, как в исходном менеджере, управляет клиент.

`changeId(cardId, OUT newId, OUT errCode)` должна сама управлять транзакцией и фиксировать новый ID:
код 0 — успех, код 1 — аккаунт не найден. Порядок параметров соответствует ранее созданной процедуре.
При отсутствии нужных прав/процедуры выводится ошибка MySQL. Обход прав, создание процедур и автоматические повторы изменений не выполняются.

## Проверки

```powershell
py -m unittest discover -s tests -v
```

Автономные тесты используют имитации MySQL/USB: поиск и выбор по карте, поля и их границы,
конкурентное изменение, обрыв связи, пароль с ведущими нулями, вызов changeId,
отмена и обязательное подтверждение наклейки, восстановление после выхода,
запись card_id, отказ пищалки, работа без считывателя, повторное подключение,
подавление повторов удерживаемой карты, клавиатурный ввод Windows.
Они не изменяют настоящую БД и карты. Реальное устройство и сервер БД в среде сборки недоступны.
