# CYBERWALL - менеджмент для мастеров

**cyberwall_master_manager v2.2.1**, Python 3.11+. Консольная программа для аккаунтов,
карт и прав доступа к замкам. Для USB используется независимая **wcopy_reader v1.4.3**.

Исходники хранятся в двух репозиториях:

- [CyberpunkMasterManager](https://github.com/limbura/CyberpunkMasterManager) — программа;
- [CyberpunkPcRfidReader](https://github.com/limbura/CyberpunkPcRfidReader) — библиотека считывателя.

В версии 2.2.1 убрана вложенная папка `cyberwall_master_manager`: главный файл,
`config.toml`, `start.bat` и этот README лежат непосредственно в
`CyberpunkMasterManager/cyberwall_master_manager_v2.2.1/`.
Библиотека не входит в исходную папку этой версии; готовый ZIP-сборщик добавляет её отдельно.

## Запуск из репозитория

1. Размести оба репозитория рядом, например в общей папке `Cyberpunk`.
2. Проверь наличие следующих файлов относительно этой общей папки:

| Компонент | Путь |
|---|---|
| Программа | `CyberpunkMasterManager/cyberwall_master_manager_v2.2.1/cyberwall_master_manager.py` |
| Настройки | `CyberpunkMasterManager/cyberwall_master_manager_v2.2.1/config.toml` |
| Библиотека | `CyberpunkPcRfidReader/wcopy_reader_package_v1.4.3_beep_duration/wcopy_reader.py` |

3. В `config.toml` задай параметры подключения к БД. Для указанной структуры путь
   библиотеки уже настроен правильно:

```toml
library_path = "../../CyberpunkPcRfidReader/wcopy_reader_package_v1.4.3_beep_duration"
```

Два `../` поднимают от папки версии до общей папки `Cyberpunk`. Путь считается от
папки программы, независимо от текущей папки терминала. Если папки расположены иначе,
измени путь; можно использовать абсолютный путь с `/`, например:

```toml
library_path = "F:/Documents/Arduino/MG NW/Cyberpunk/CyberpunkPcRfidReader/wcopy_reader_package_v1.4.3_beep_duration"
```

Папка должна непосредственно содержать `wcopy_reader.py`. Если снова добавить
вложенную папку программы, относительный путь потребуется пересчитать.

4. Запусти `start.bat` двойным щелчком. Либо из PowerShell / терминала VS Code,
   открытого в корне репозитория программы:

```powershell
cd .\cyberwall_master_manager_v2.2.1
.\start.bat
```

### Что делает start.bat

- Ищет Python 3.11 или новее через `py`, стандартные папки установки и PATH.
- Если подходящего Python нет, устанавливает Python 3.13 через `winget` для текущего
  пользователя. Соглашения источника и пакета принимаются автоматически.
- Если `winget` недоступен, предлагает установить «Установщик приложений» из Microsoft
  Store либо Python вручную; сам `winget` файл не устанавливает.
- При отсутствии `pip` вызывает `ensurepip`.
- При каждом запуске выполняет `pip install -r requirements.txt` для выбранного Python.
  Уже подходящие версии не переустанавливаются; `--upgrade` для зависимостей не используется.
- После успешной подготовки запускает программу тем же Python. При ошибке оставляет
  окно с сообщением открытым.

Для скачивания Python и недостающих зависимостей нужен интернет. BAT не скачивает
репозиторий библиотеки и не исправляет `library_path`: размести её и настрой путь заранее.
Скрипт использует выбранную установку Python, отдельное виртуальное окружение не создаёт.

### Ручной запуск

Если Python 3.11+ уже установлен, из папки версии:

```powershell
py -3 -m pip install -r requirements.txt
py -3 cyberwall_master_manager.py
```

В папке программы один `requirements.txt`: он включает PyMySQL и hidapi.
У библиотеки остаётся собственный `requirements.txt` для независимого использования;
для запуска менеджера отдельно устанавливать его не требуется.

Считыватель не обязателен. Основная программа допускает работу без устройства,
без папки библиотеки или без hidapi. Для установки только драйвера БД вручную:
`py -3 -m pip install "PyMySQL[rsa]>=1.1,<2"`, затем `py -3 cyberwall_master_manager.py`.
В этом случае запускай Python-файл напрямую: `start.bat` всё равно обрабатывает
полный `requirements.txt`, включая hidapi, даже при `reader.enabled = false`.
Без USB сохраняются поиск с клавиатуры и действия с БД; запись карты недоступна.
USB считыватель можно подключить во время работы, все другие программы работающие
со считывателем должны быть закрыты. При нескольких считывателях оставь подключённым один.

## Обновление программы и запуск готового ZIP

Перенеси свои параметры подключения в новый `config.toml`. Если после работы со старой
версией остался `pending_id_change.json`, перенеси его в новую папку программы:
он нужен, чтобы закончить подтверждение наклейки. Не переноси старые модули поверх новых.

Готовый архив от `build_release.py` имеет другую структуру, чем исходники репозитория:

- `cyberwall_master_manager/` — программа, настройки, внутренние модули, тесты и сборщик;
- `wcopy_reader_package/` — выбранная библиотека, её примеры, документация и тесты;
- `BUILD_MANIFEST.json` — версии и SHA-256 файлов сборки.

Распакуй весь архив в новую папку, сохрани две соседние папки. Проверь настройки БД
в `cyberwall_master_manager/config.toml` и запусти `cyberwall_master_manager/start.bat`.
В готовом архиве путь библиотеки уже заменён на `../wcopy_reader_package`.
Для такой сборки отдельное клонирование репозитория считывателя не требуется.

## Сборка из двух репозиториев

Обнови нужные версии программы и библиотеки. Из папки
`CyberpunkMasterManager/cyberwall_master_manager_v2.2.1` выполни:

```powershell
py -3 build_release.py --reader "../../CyberpunkPcRfidReader/wcopy_reader_package_v1.4.3_beep_duration" --output "../builds/cyberwall_master_manager_v2.2.1.zip"
```

Папка `--reader` должна непосредственно содержать `wcopy_reader.py` и `requirements.txt`.
Относительные аргументы `--reader` и `--output` считаются от текущей папки терминала.
Сам код программы сборщик всегда берёт из папки, где лежит `build_release.py`.

**Сборщик не читает `reader.library_path` из config.toml.** Без `--reader` он ищет
`../wcopy_reader_package` относительно своей папки. Это подходит для готового ZIP,
но не для нынешней структуры исходников: используй явный `--reader`, как в примере.

Сборщик не скачивает обновления, не запускает тесты и не устанавливает зависимости.
Он копирует текущие файлы программы, включая текущий `start.bat`, и выбранную библиотеку
в две соседние папки ZIP. Исходные файлы библиотеки и конфигурация на диске не изменяются.
Единый `requirements.txt` внутри сборки формируется из PyMySQL и зависимостей библиотеки.
Локальные ссылки и нестандартные параметры pip в её зависимостях приводят к ошибке сборки.

Сборщик исключает журнал незавершённой смены ID программы, кэш Python, Git-файлы
и временные логи библиотеки. В копии `config.toml` внутри ZIP он сохраняет настройки
БД и прочие параметры, но заменяет путь библиотеки на `../wcopy_reader_package`,
а путь журнала — на `pending_id_change.json`. Проверь настройки перед распространением.
Пароль БД в конфигурации не хранится. Существующий архив не перезаписывается.

**Python и скачанные пакеты зависимостей в ZIP не включаются.** Это исходный комплект,
не EXE и не офлайн-установщик. На чистом ПК первый запуск требует интернет для установки
Python и зависимостей. На подготовленном ПК программа может работать без интернета,
если сервер MySQL доступен, например по локальной сети.

В репозитории также сохранены исторические папки 2.0.1 и 2.1 со своими копиями
библиотеки. Они не используются версией 2.2.1 и не включаются её сборщиком.
Рабочие `__pycache__`, `*.pyc`, `pending_id_change.json` и готовые ZIP не следует
добавлять в Git; старые версии программы удобнее хранить в истории и тегах.

## Настройки

Всё, что обычно требуется менять, находится в `config.toml`:

| Раздел | Настройки |
|---|---|
| database | host, port, user, name; тайм-ауты подключения, чтения и записи |
| interface | page_size — количество строк таблицы на странице |
| reader | enabled; library_path; write_beep_t; тайм-аут и интервалы опроса/восстановления |
| state | pending_id_file — журнал обязательного подтверждения наклейки |

В TOML используются `true`/`false`, строки в кавычках. Для путей Windows удобно
использовать `/`, например `D:/Projects/wcopy_reader_package`.
Настройки читаются при запуске. При ошибке конфигурации выводится объяснение.
Пароль БД вводится скрыто; если введена кириллица, программа просит переключить
раскладку и повторить только пароль, не пытаясь подключиться с этим вводом.

## Поиск и таблицы

Вводи имя, описание замка, ID, card_id или часть номера. Enter показывает всех;
n/p переключают страницы; номер строки выбирает запись; :b — назад; :q — выход.
В общем поиске команда **:new — создать новый аккаунт**.

На любом этапе поиска аккаунта можно приложить карту без Enter. Поиск идёт по
`main.card_id`, не по UID чипа и не по ID с наклейки. Для повторного выбора той же
карты убери её и приложи снова. Ввод Windows с исправлением задержек сохранён.

Таблицы имеют заголовки, в ячейках — только значения. Пустые или неприменимые значения
показаны как `-`, кроме **полицейских прав аккаунта: и NULL, и 0 отображаются как 0**.
Для строки замка неприменимые полицейские права остаются `-`.

## Меню аккаунта и замка

| Пункт | Аккаунт | Замок |
|---|---|---|
| 1 | Назначить доступ к замкам | Назначить доступ к замкам |
| 2 | Отозвать доступ к замкам | Отозвать доступ к замкам |
| 3 | Обновить данные о записи | Обновить данные о записи |
| 4 | Изменить имя | Изменить описание замка |
| 5 | Изменить деньги | Удалить замок |
| 6 | Изменить рейт | |
| 7 | Изменить уровень деки | |
| 8 | Изменить полицейские права | |
| 9 | Посмотреть и изменить пароль | |
| 10 | Изменить ID | |
| 11 | Записать карту | |
| 12 | Удалить аккаунт | |

В меню замка список называется «Аккаунты с правом доступа».
Аккаунт может представлять персонажа, организацию или другую сущность.

Деньги и рейт при изменении — новый итоговый баланс, допустим signed INT:
−2 147 483 648…2 147 483 647. Уровень деки — 0…255. Полицейские права — 0/1.
Снятие прав сохраняет SQL NULL, отображаемый как 0; `-` и `null` также принимаются.
Если в БД уже 0, повторное снятие не делает лишний UPDATE. Массового изменения старых записей нет.

Имя: **1–3 слова, каждое не длиннее 11 символов, включая дефисы, цифры и пунктуацию**.
Разделители слов — пробелы. Лишние слова и каждое слишком длинное слово перечисляются
в ошибке; сохранение запрещено, пока ввод не исправлен. Эти правила действуют при
создании аккаунта и изменении имени. Существующие имена сами не переписываются.

Пароль аккаунта — строка, ведущие нули и пробелы сохраняются. Перед изменением
показывается текущий пароль. Enter / :b — назад; :empty — установить пустую строку.
Пароль аккаунта может содержать кириллицу: проверка раскладки применяется только к паролю БД.
Описание замка ограничивается только типом/длиной поля в БД; правила имени аккаунта
к нему не применяются. :empty задаёт пустую строку, :null — NULL, если разрешён схемой.

Изменения требуют подтверждения. Параллельное изменение редактируемого поля другим
подключением приводит к отмене сохранения и предложению обновить запись.

## Создание аккаунта

В общем поиске введи **:new**. Программа читает фактические столбцы main и предлагает
заполнить каждый обычный столбец, исключая `card_id`, `id` и генерируемые БД столбцы.
Для текущей схемы это name, password, money, losa, netrunner_lvl, police, occupancy,
joinrpg_id. Порядок соответствует таблице БД.

На каждом шаге показываются ограничения типа, длины, диапазона, допустимость NULL
и значение по умолчанию. Для имени дополнительно применяются правила 3 слов / 11 символов.
Enter использует показанное значение по умолчанию либо NULL, если так указано;
:null задаёт NULL явно, :empty — пустую строку. Команды :b/:q отменяют ввод до записи.
JoinRPG ID, если указан, должен быть уникальным. Пароль сохраняется как текст.

После заполнения показывается сводка всех полей и запрашивается подтверждение.
Выполняется один INSERT без card_id и id: их формируют AUTO_INCREMENT и триггер БД.
Программа читает сформированные номера в той же транзакции, проверяет девятизначный ID,
затем подтверждает создание. Если требуемые номера не сформированы, транзакция откатывается.
Неиспользованный номер AUTO_INCREMENT после отката может быть пропущен — это нормально.
При успехе открывается аккаунт и выводится напоминание написать ID на наклейке;
запись card_id в память карты выполняется отдельно пунктом 11.

Поддерживаются целочисленные поля, CHAR/VARCHAR и TEXT. Если в схеме появился другой
редактируемый тип, форма объяснит, какое поле требует поддержки; INSERT не выполняется.
Программа не меняет структуру main, триггеры или реестр ID.

## Удаление

Аккаунт: пункт 12, подтверждение точным **ID**, а не card_id.
Замок: пункт 5, подтверждение **lock_id**. Номер можно вводить с пробелами между разрядами.
Ошибочный номер не удаляет запись; Enter / :b отменяет действие.

Удаление записи и её строк lock_access выполняется в одной транзакции. Перед DELETE
строка блокируется, и ещё раз проверяется ID аккаунта или описание замка. При ошибке,
включая недостаток прав или внешний ключ, вся операция откатывается.
Программа не удаляет logs и id_registry и не сбрасывает AUTO_INCREMENT. Физическая
карта при удалении аккаунта не стирается. Существующие триггеры БД продолжают действовать.

## Смена ID и запись карты

ID на наклейке — main.id, номер в памяти карты — main.card_id.
Пункт 10 вызывает `changeId(cardId, OUT newId, OUT errCode)` после предупреждения.
Выводится **ID ИЗМЕНЕН**, затем новый ID и обязательное подтверждение обновления наклейки.
При ошибке ввода явно сообщается о неправильном ID. Незавершённое подтверждение
сохраняется в pending_id_change.json и восстанавливается после запуска; повторного CALL нет.
Не удаляй журнал до завершения подтверждения. Используй одну копию программы из этой папки.

Пункт 11: приложи одну карту и подтверди запись. В память записывается выбранный card_id;
после успешной проверки обратным чтением выводится напоминание сверить ID на наклейке.
Перед записью библиотека заново опрашивает устройство; отсутствие карты не считается
успехом. После любой попытки фоновый опрос возобновляется, в том числе после ошибки.
Он работает во всех меню, поддерживая штатные цвет и звук; выбор аккаунта по карте
разрешён только в поиске. Дополнительный писк вызывается только после записи, T=10.

Все исправления ввода, опроса и восстановления индикации находятся в коде программы
(modules/card_console.py, modules/windows_console.py), **не в wcopy_reader.py**.
Протокол, ключ, расположение номера и проверка записи остаются библиотечными.
При обрыве БД результат изменения может быть неопределённым; автоматического повтора
INSERT/UPDATE/DELETE/CALL нет. После восстановления связи проверь данные.

## Права БД

Помимо SELECT на main, locks, lock_access и EXECUTE на setLockAccess/changeId, нужны:

- INSERT и DELETE на main — создание/удаление аккаунтов;
- UPDATE колонок name, money, losa, netrunner_lvl, police, password таблицы main;
- UPDATE(description) и DELETE на locks — новые действия с замками;
- DELETE на lock_access — очистка прав при удалении аккаунта/замка.

Прямой UPDATE main.id или main.card_id не используется. `police` должен допускать NULL.
Программа не меняет привилегии и не выполняет миграций автоматически.
Если у прежнего master отсутствуют новые права, их должен добавить администратор БД.
Для атомарных операций таблицы и затрагиваемые триггерами таблицы должны быть транзакционными
(InnoDB). История действий самостоятельно не добавляется в logs, работают существующие триггеры.

## Проверки

Из папки `cyberwall_master_manager_v2.2.1`:

```powershell
py -3 -m unittest discover -s tests -v
```

Для полного набора тестов настрой путь к библиотеке и размести её из отдельного
репозитория, как описано выше. Некоторые тесты подменяют её функции, поэтому сам
модуль `wcopy_reader.py` должен быть доступен, хотя физический USB-считыватель не нужен.

64 автоматические проверки используют имитации MySQL/USB: ввод, поиск по карте,
фоновые опросы, восстановление после ошибки записи, создание/удаление, SQL-параметры,
откаты, конкурентные изменения и состав ZIP. Сервер MySQL для этих проверок не нужен.
`start.bat` и `build_release.py` не запускают тесты автоматически.
Реальные подключения к БД, USB-считыватель и запуск BAT проверяются отдельно на Windows.
