# CYBERWALL - менеджмент для мастеров

**cyberwall_master_manager**, Python 3.11+. Консольная программа для работы с аккаунтами,
картами, правами доступа к замкам и т.д. Для USB считывателя RFID используется независимая библиотека **wcopy_reader** (отдельный репозиторий CyberpunkPcRfidReader).

Основные исходники и библиотеки хранятся отдельно:

- [CyberpunkMasterManager](https://github.com/limbura/CyberpunkMasterManager) — программа;
- [CyberpunkPcRfidReader](https://github.com/limbura/CyberpunkPcRfidReader) — библиотека считывателя;
- CyberpunkIdPrinter — необязательный пакет `cyberwall_id_printer` для термопринтера;
- TiMini-Print — внешний транспорт и протоколы печати; не копируются в менеджер.

Библиотека **wcopy_reader** не входит в исходную папку этой версии; сборщик встраивает её в готовый EXE.
Готовый Windows ZIP содержит Python и зависимости и запускается без их установки и без интернета.

Текущая версия программы — **2.6.0**. Номер версии задаётся в
[`cyberwall_master_manager/cyberwall_master_manager.py`](cyberwall_master_manager/cyberwall_master_manager.py),
в переменной `VERSION`. Имя папки программы от версии не зависит.
При выпуске новой версии обнови также номер в этом README; имя ZIP сборщик формирует из `VERSION`.

## Запуск из репозитория

1. Размести оба репозитория рядом, например в общей папке `Cyberpunk`.
2. Проверь наличие следующих файлов относительно этой общей папки:

| Компонент | Путь |
|---|---|
| Программа | `CyberpunkMasterManager/cyberwall_master_manager/cyberwall_master_manager.py` |
| Настройки | `CyberpunkMasterManager/cyberwall_master_manager/config.toml` |
| Библиотека | `CyberpunkPcRfidReader/wcopy_reader_package/wcopy_reader.py` |

3. В `config.toml` задай параметры подключения к БД по умолчанию и путь к библиотеке считывателя, например:

```toml
library_path = "../../CyberpunkPcRfidReader/wcopy_reader_package"
```

Папка должна непосредственно содержать `wcopy_reader.py`.

Два `../` поднимают от папки программы до общей папки `Cyberpunk`. Путь считается от
папки программы, независимо от текущей папки терминала. Если папки расположены иначе,
измени путь; можно использовать абсолютный путь с `/`, например:

```toml
library_path = "F:/Documents/Arduino/MG NW/Cyberpunk/CyberpunkPcRfidReader/wcopy_reader_package"
```

4. Запусти `start.bat` двойным щелчком. Либо из PowerShell / терминала VS Code,
   открытого в корне репозитория программы:

```powershell
cd .\cyberwall_master_manager
.\start.bat
```

### Что делает start.bat

- Ищет Python 3.11 или новее через `py`, стандартные папки установки и PATH.
- Если подходящего Python нет, устанавливает Python 3.13 через `winget` для текущего
  пользователя. Соглашения источника и пакета принимаются автоматически.
- Если `winget` недоступен, предлагает установить «Установщик приложений» из Microsoft
  Store либо Python вручную; сам `winget` файл не устанавливает.
- При отсутствии `pip` вызывает `ensurepip`.
- При каждом запуске проверяет и при необходимости устанавливает требующиеся зависимости:
  `pip install -r requirements.txt` для выбранного Python.
  Уже подходящие версии не переустанавливаются; `--upgrade` для зависимостей не используется.
- После успешной подготовки запускает программу тем же Python. При ошибке оставляет
  окно с сообщением открытым.

Для скачивания Python и недостающих зависимостей нужен интернет. BAT не скачивает
репозиторий библиотеки и не исправляет `library_path`: размести её и настрой путь заранее.
Скрипт использует выбранную установку Python, отдельное виртуальное окружение не создаёт.

### Ручной запуск

Если Python 3.11+ уже установлен, из папки с программой:

```powershell
py -3 -m pip install -r requirements.txt
py -3 cyberwall_master_manager.py
```

В папке программы есть `requirements.txt`: он включает PyMySQL и hidapi.
У библиотеки остаётся собственный `requirements.txt` для независимого использования;
для запуска менеджера отдельно устанавливать его не требуется.

Считыватель RFID не обязателен. Основная программа допускает работу без устройства,
без папки библиотеки или без hidapi. Для установки только драйвера БД вручную:
`py -3 -m pip install "PyMySQL[rsa]>=1.1,<2"`, затем `py -3 cyberwall_master_manager.py`.
В этом случае запускай Python-файл напрямую: `start.bat` всё равно обрабатывает
полный `requirements.txt`, включая hidapi, даже при `reader.enabled = false`.
Без считывателя сохраняются поиск с клавиатуры и действия с БД; запись карты недоступна.
Считыватель можно подключить во время работы, все другие программы работающие
со считывателем должны быть закрыты. Должен быть подключен только один считыватель.

## Офлайн-комплект для конечных пользователей

`build_release.py` создаёт **Windows x64 ZIP с готовым EXE**. Его можно скопировать
на ПК без интернета, Python и установленных библиотек. Всё нужное для запуска упаковано
в комплект. Доступ к серверу MySQL всё равно нужен, например по локальной сети.

В архиве находится одна папка `cyberwall_master_manager`:

| Содержимое | Назначение |
|---|---|
| `cyberwall_master_manager.exe` | Запуск программы |
| `_internal/` | Python, нативные DLL/PYD и встроенные библиотеки |
| `config.toml` | Редактируемые настройки подключения и программы |
| `README.txt` | Короткая инструкция пользователю |
| `LICENSES/` | Лицензии упакованных компонентов |
| `BUILD_INFO.json` | Версии Python, программы, считывателя и зависимостей |

Распакуй **весь ZIP**, при необходимости измени настройки БД и запусти EXE.
Запускать из архива или переносить только один EXE нельзя: нужна вся папка.
Исходники программы, тесты, сборщик, Git, исходный `start.bat`, pip и установщики
в пользовательский комплект не добавляются. Упаковка EXE не является защитой исходников.

Настройки и рабочие журналы `pending_id_change.json` / `batch_cards.json` находятся рядом с EXE, а не в `_internal`.
Папка должна разрешать запись. При обновлении распакуй новую версию отдельно и перенеси
свои настройки, незавершённый журнал смены ID и журнал пакетной записи, если они остались. Используй одну
запущенную копию программы из этой папки.

Библиотека `wcopy_reader` встроена в EXE. В готовой сборке `reader.library_path`
игнорируется; другие настройки считывателя работают. Для изменения версии библиотеки
собери новый комплект. При запуске исходного `.py` внешний путь продолжает использоваться.

## Сборка офлайн-комплекта

Собирать Windows EXE нужно **на Windows x64 с Python 3.11+**; рекомендуется Python
**3.13 x64**. Сборщик не является кросс-компилятором и на Linux/macOS завершится
с объяснением. На сборочном ПК обычно нужен интернет; на ПК конечного пользователя — нет.

Размести рядом CyberpunkMasterManager, CyberpunkPcRfidReader, CyberpunkIdPrinter
и чистый TiMini-Print на закреплённой ревизии. Для проверки исходников нужен Git. Из папки `cyberwall_master_manager` выполни:

```powershell
py -3.13 build_release.py
```

Если Python 3.13 не установлен, можно установить его через
`winget install --id Python.Python.3.13 --exact --source winget --scope user`.
С другой совместимой 64-битной версией Python команда — `py -3 build_release.py`.

Пути берутся из `config.toml`: `reader.library_path`, `printer.library_path`
и `printer.timini_path`. Библиотека печати обязательна для полной сборки.
Он считается от папки программы. При необходимости можно явно задать другую библиотеку
и имя архива:

```powershell
py -3.13 build_release.py --reader "../../CyberpunkPcRfidReader/wcopy_reader_package" --output "../builds/cyberwall_master_manager_windows_x64.zip"
```

Относительные аргументы `--reader`, `--printer`, `--timini` и `--output` считаются от текущей папки терминала.
Без `--output` результат сохраняется в `../builds/` относительно папки сборщика;
имя содержит VERSION из программы и суффикс `_windows_x64.zip`. Уже существующий ZIP
не перезаписывается. Папка библиотеки должна содержать `wcopy_reader.py` и `requirements.txt`.

Сборщик автоматически:

1. Создаёт временное изолированное Python-окружение; установленное рабочее окружение не меняет.
2. Проверяет ревизию и чистоту TiMini, устанавливает PyInstaller, библиотеку печати
   и все зависимости, включая Bluetooth/WinRT, Pillow и PDFium.
3. Упаковывает EXE, `hidapi`, `cryptography`, библиотеку печати, runtime-модули TiMini
   и JSON-каталог устройств. Git и внешние исходники для запуска не нужны.
4. Кладёт рядом `config.toml`, короткую инструкцию и лицензии. Настройки БД сохраняются;
   журнал сбрасывается на локальный путь, `library_path` помечается как `bundled`.
5. Переносит собранную папку в путь с пробелами и кириллицей и выполняет `--self-test`
   с PATH без сборочного Python. Проверяются загрузка конфигурации, считывателя/HID,
   версии, RSA-ветка MySQL, Windows BLE/WinRT, четыре макета и серия страниц.
   БД, USB и Bluetooth-устройства не открываются.
6. Создаёт ZIP, распаковывает его в другую папку и повторяет самопроверку EXE.
   При ошибке ZIP удаляется. Временная сборочная папка удаляется.

Ни исходники независимой библиотеки, ни исходный `config.toml` не изменяются.
Рабочие журналы смены ID и пакетной записи в архив не попадают. Репозитории сборщик сам не скачивает
и не обновляет. Проверь параметры БД в конфигурации перед распространением.
Если для используемой версии Python не нашлись готовые пакеты, установка завершается
ошибкой: попробуй рекомендованный Python 3.13 x64; компилятор C++ не требуется.

Для заранее подготовленного сборочного окружения есть `--no-install`: сборщик использует
текущий Python и не запускает pip. В нём уже должны быть PyInstaller 6.16+ версии 6.x,
зависимости менеджера и библиотеки. Это режим для сборщика, конечному пользователю он не нужен.

### Сборка на GitHub

Полный ZIP собирает workflow **Windows standalone manager** в приватном репозитории
[CyberpunkIdPrinter](https://github.com/limbura/CyberpunkIdPrinter/actions/workflows/windows-manager.yml).
**Actions → Windows standalone manager → Run workflow**, параметр `manager_ref` —
ветка или коммит менеджера (по умолчанию `master`). Сборка запускается также при
изменениях исходников библиотеки печати. После изменений только менеджера запусти
её вручную. Считыватель и TiMini берутся по закреплённым коммитам.

Workflow расположен в репозитории библиотеки печати, поскольку он приватный:
стандартный токен Actions публичного менеджера не имеет доступа к его исходникам.
Дополнительные секреты не нужны, видимость репозиториев не меняется. В репозитории
менеджера workflow **Manager tests** по-прежнему проверяет изменения на Windows.

После успешного запуска скачай **Artifacts → cyberwall-master-manager-windows-x64**
и извлеки находящийся внутри пользовательский ZIP. Артефакт хранится 30 дней;
это не GitHub Release. Workflow не публикует релизы и не меняет код репозиториев.

Целевая система — **Windows 10/11 x64**. Все программные зависимости включены,
но для реальной работы нужны доступ к БД, Bluetooth-адаптер и системные драйверы
оборудования. Самопроверка с очищенным PATH не заменяет испытание на физическом ПК
с термопринтером и USB-считывателем.

## Настройки

Всё, что обычно требуется менять, находится в `config.toml`:

| Раздел | Настройки |
|---|---|
| database | host, port, user, name; тайм-ауты подключения, чтения и записи |
| interface | page_size — количество строк таблицы на странице |
| reader | enabled; library_path; write_beep_t; тайм-аут и интервалы опроса/восстановления |
| state | pending_id_file — журнал подтверждения наклейки; batch_cards_file — журнал пакетной записи |

В TOML используются `true`/`false`, строки в кавычках. Для путей Windows удобно
использовать `/`, например `D:/Projects/wcopy_reader_package`.
Настройки читаются при запуске. При ошибке конфигурации выводится объяснение.
Пароль БД вводится скрыто; если введена кириллица, программа просит переключить
раскладку и повторить только пароль, не пытаясь подключиться с этим вводом.

## История ввода и сохранённое подключение

**↑ / ↓** подставляют предыдущую / следующую строку текущего поля. Строку можно
редактировать; выполнение происходит только по **Enter**. Возврат вниз за последнюю
запись восстанавливает текст, набранный до просмотра истории.

История поиска, выбора кандидатов, меню аккаунта/замка и каждого редактируемого поля
раздельная. Пустые строки и одинаковые подряд не добавляются; хранится до 100 строк
на поле. История живёт только в памяти, очищается при отключении от БД и не сохраняется
между запусками. В паролях, подтверждениях изменений/удаления/наклейки и **во всём
пакетном режиме истории нет**. Номера, полученные от считывателя, в неё не попадают.
Расширенный редактор работает в интерактивных терминалах Windows и Linux/macOS;
при перенаправленном вводе используется обычный построчный ввод.

При первом запуске вводятся сервер, порт, пользователь, **имя базы данных** и пароль.
Программа запоминает параметры только после успешного подключения и проверки доступа
к таблицам. Следующий запуск автоматически подключается с ними. Если сервер недоступен,
пароль изменился или сохранённые данные не читаются, программа переходит к ручному входу.
Пароль при ручном входе всегда вводится заново и скрыто.

Пункт **`:menu` → 5 — отключиться от БД** доступен в общем поиске и меню выбранного
аккаунта/замка. Он закрывает соединение, удаляет сохранённый вход, очищает историю ввода
и предлагает параметры нового подключения. Прежние сервер/порт/пользователь/база остаются
подсказками в скобках; новый успешный вход сохраняется. Если выйти из этого запроса через
`:q`, следующий запуск также предложит ручной вход. Журналы карт и смены ID не удаляются;
при смене базы их привязка к серверу и имени БД продолжает проверяться.

Сохранённое подключение общее для копий менеджера, запущенных одним пользователем ОС:

- **Windows:** `%LOCALAPPDATA%/CYBERWALL/cyberwall_master_manager/connection.dat`.
  Все параметры, включая пароль, зашифрованы DPAPI для текущего пользователя Windows.
  Перенос этого файла на другой компьютер/пользователя обычно не позволяет его расшифровать:
  там нужно войти заново. Дополнительные пакеты для шифрования не нужны.
- **Linux/macOS:** `$XDG_STATE_HOME/CYBERWALL/cyberwall_master_manager/connection.dat`,
  по умолчанию `~/.local/state/CYBERWALL/cyberwall_master_manager/connection.dat`.
  Приватный файл с правами `0600`, каталог `0700`; **пароль хранится без шифрования**.

Сохранённое подключение находится вне репозитория и готового ZIP. При обновлении программы
на том же компьютере оно сохраняется. `config.toml` задаёт значения первого входа;
его изменение не заменяет уже сохранённое подключение — используй `:menu` → 5.
Для сброса входа при закрытой программе можно удалить указанный `connection.dat`.

## Поиск и таблицы

Вводи имя, описание замка, ID, card_id или часть номера. Enter показывает всех;
n — следующая страница; p — предыдущая страница; номер строки выбирает запись; :b — назад; :q — выход.
В общем поиске команда **:menu → 1 — создать аккаунт**.

На любом этапе поиска аккаунта можно приложить карту без Enter. Поиск идёт по
`main.card_id`, не по UID чипа и не по ID с наклейки. Для повторного выбора той же
карты убери её и приложи снова. Ввод Windows с исправлением задержек сохранён.

Таблицы имеют заголовки, в ячейках — только значения. Пустые или неприменимые значения
показаны как `-`, кроме **полицейских прав аккаунта: и NULL, и 0 отображаются как 0**.
Для строки замка неприменимые полицейские права остаются `-`.

## Меню аккаунта и замка

| Пункт | Аккаунт | Замок |
|---|---|---|
| 1 | Назначить доступ к замкам | Назначить доступ к замкам |
| 2 | Отозвать доступ к замкам | Отозвать доступ к замкам |
| 3 | Обновить данные о записи | Обновить данные о записи |
| 4 | Изменить имя | Изменить описание замка |
| 5 | Изменить деньги | Удалить замок |
| 6 | Изменить рейт | |
| 7 | Изменить уровень деки | |
| 8 | Изменить полицейские права | |
| 9 | Посмотреть и изменить пароль | |
| 10 | Изменить ID | |
| 11 | Записать карту | |
| 12 | Удалить аккаунт | |

В меню замка список называется «Аккаунты с правом доступа».
Аккаунт может представлять персонажа, организацию или другую сущность.

Деньги и рейт при изменении — новый итоговый баланс, допустим signed INT:
−2 147 483 648…2 147 483 647. Уровень деки — 0…255. Полицейские права — 0/1.
Снятие прав сохраняет SQL NULL, отображаемый как 0; `-` и `null` также принимаются.
Если в БД уже 0, повторное снятие не делает лишний UPDATE. Массового изменения старых записей нет.

Имя: **1–3 слова, каждое не длиннее 11 символов, включая дефисы, цифры и пунктуацию**.
Разделители слов — пробелы. Лишние слова и каждое слишком длинное слово перечисляются
в ошибке; сохранение запрещено, пока ввод не исправлен. Эти правила действуют при
создании аккаунта и изменении имени. Существующие имена сами не переписываются.

Пароль аккаунта — строка, ведущие нули и пробелы сохраняются. Перед изменением
показывается текущий пароль. Enter, :b — назад; :empty — установить пустую строку.
Пароль аккаунта может содержать кириллицу: проверка раскладки применяется только к паролю БД.
Описание замка ограничивается только типом/длиной поля в БД; правила имени аккаунта
к нему не применяются. :empty задаёт пустую строку, :null — NULL, если разрешён схемой.

Изменения требуют подтверждения. Параллельное изменение редактируемого поля другим
подключением приводит к отмене сохранения и предложению обновить запись.

## Создание аккаунта

В общем поиске введи **:menu → 1**. Программа читает фактические столбцы main и предлагает
заполнить каждый обычный столбец, исключая `card_id`, `id`, `joinrpg_id` и генерируемые БД столбцы.
Для текущей схемы это name, password, money, losa, netrunner_lvl, police и occupancy
(принадлежность). Порядок соответствует таблице БД.
ID заявки JoinRPG не запрашивается: при создании аккаунта `joinrpg_id` всегда записывается как NULL.

На каждом шаге показываются ограничения типа, длины, диапазона, допустимость NULL
и значение по умолчанию. Для имени дополнительно применяются правила 3 слов / 11 символов.
Enter использует показанное значение по умолчанию либо NULL, если так указано;
:null задаёт NULL явно, :empty — пустую строку. Команды `:b` и `:q` отменяют ввод до записи.
Пароль сохраняется как текст.

После заполнения показывается сводка всех полей и запрашивается подтверждение.
Выполняется один INSERT без card_id и id: их формируют AUTO_INCREMENT и триггер БД.
Программа читает сформированные номера в той же транзакции, проверяет девятизначный ID,
затем подтверждает создание. Если требуемые номера не сформированы, транзакция откатывается.
Неиспользованный номер AUTO_INCREMENT после отката может быть пропущен — это нормально.
При успехе открывается аккаунт и выводится напоминание написать ID на наклейке;
запись card_id в память карты выполняется отдельно пунктом 11.

Поддерживаются целочисленные поля, CHAR/VARCHAR и TEXT. Если в схеме появился другой
редактируемый тип, форма объяснит, какое поле требует поддержки; INSERT не выполняется.
Программа не меняет структуру main, триггеры или реестр ID.

## Пакетная запись карт

В общем поиске введи **:menu → 2**. Нужна **wcopy_reader 1.4.4+**: в ней появилась
проверка ожидаемого UID и содержимого блока до отправки команды записи.
В готовом EXE библиотека уже встроена; для запуска исходников обнови оба репозитория.
Старый config.toml без batch_cards_file продолжает работать: по умолчанию используется batch_cards.json.

Выбери **«начать новую работу»** или **«продолжить работу»**. При новом запуске
сохраняется список существующих аккаунтов по возрастанию card_id. Никакого отдельного
номера очереди нет: пропуски card_id допустимы. Позднее созданные аккаунты попадут
в следующую новую работу, а текущий список сохраняет прежний состав.

Цикл для каждой карты:

1. Экран очищается. В фиксированных строках показаны **card_id, ID и имя**.
   Принадлежность не показывается. Прогресс и подсказки расположены ниже.
2. Наклей наклейку и напиши ID и имя. Положи одну карту на считыватель.
3. Введи **полный ID с наклейки** и нажми Enter. Пробелы между цифрами разрешены.
   Несовпадение не переключает аккаунт и не запускает запись.
4. Программа читает карту, проверяет её и записывает текущий main.card_id.
   Дополнительное подтверждение для карты с нулевым номером не требуется.
5. После проверки UID и всего блока появляется **«ЗАПИСАНО И ПРОВЕРЕНО»** и отдельный писк.
6. Убери карту. После двух последовательных ответов «нет карты» экран очищается
   и открывается следующий незавершённый и не пропущенный аккаунт.

При вводе ID программа не считывает наклейку — читай цифры именно с неё, не с экрана.
Имя сверь глазами. Используй обычное окно терминала: при перенаправлении вывода в файл
экран не очищается. В узком окне длинные строки обрезаются; увеличь ширину окна для полного имени.

| Команда | Действие |
|---|---|
| `:skip` | Пропустить текущий аккаунт без изменений БД |
| `:card 87` | Перейти к существующему card_id 87 в сохранённом списке |
| `:id 123456789` | Найти аккаунт по текущему ID в БД и перейти к нему, если он входит в список |
| `:skipped` | Показать пропущенные; можно ввести card_id для возврата |
| `:report` | Показать все аккаунты с результатами и путь к журналу |
| `:next` | Перейти дальше, не меняя статус текущего аккаунта |
| `:r` | Разрешить повторную запись уже готового аккаунта; затем вновь ввести ID |
| `:b`, `:q` | Выйти из пакетного режима, сохранив прогресс |

Ctrl+C также завершает пакетный режим. При ожидании снятия карты используй Ctrl+C,
если нужно прерваться. После окончания списка доступны отчёт, пропущенные и переходы.

**Защиты от ошибок:**

- UID, уже использованный для другого аккаунта в этой работе, повторно не записывается.
- Для номера другого существующего аккаунта показано предупреждение и требуется слово
  **ПЕРЕЗАПИСАТЬ**. Неизвестный ненулевой номер тоже требует подтверждения Enter.
- Если нужный card_id уже записан, выполняется повторное чтение UID и блока;
  результат — **«КАРТА УЖЕ СООТВЕТСТВУЕТ АККАУНТУ»**, без повторной записи.
- Подмена карты или изменение блока между проверкой и началом записи останавливают операцию.
- Перед записью повторно проверяются ID и имя в БД. Строка аккаунта блокируется
  на время аппаратной операции, чтобы её не переименовали или удалили параллельно.
- После ошибки текущий аккаунт сохраняется, автоматического повтора записи нет.
  Ошибка USB не считается снятием карты. Сбой писка не отменяет успешную проверку.
- UID и исходный номер сохраняются **до** записи, результат — **после** проверки.
  Если запись прервана или итог не удалось сохранить, при продолжении нужно заново
  подтвердить наклейку и проверить карту. Положительный результат не предполагается.

Настройка `[state] batch_cards_file` задаёт путь журнала относительно папки программы.
Он содержит состав списка, текущее место, UID, результаты и историю попыток, но не пароль БД.
Журнал привязан к серверу, порту и имени БД. Повреждённый журнал или журнал другой БД
не перезаписывается автоматически. Для одного журнала одновременно разрешена одна копия программы.
При начале новой работы прежний журнал архивируется в соседний файл `batch_cards-<суффикс>.json`.
Текущий файл — `batch_cards.json`; архивы автоматически не подгружаются.
Сохрани текущий журнал при обновлении или переносе программы, чтобы продолжить работу.

Пакетный режим не меняет записи в БД, только читает и временно блокирует текущую строку.
Как и библиотека, он не может отличить физические карты с одинаковым UID и содержимым.
Ответ «нет карты» иногда бывает неудачным опросом; проверка повторного UID дополнительно
защищает от записи следующего аккаунта на оставшуюся карту. Настоящие карты перед
массовой работой нужно проверить на небольшом количестве.

## Удаление

Аккаунт: пункт 12, подтверждение точным **ID**, а не card_id.
Замок: пункт 5, подтверждение **lock_id**. Номер можно вводить с пробелами между разрядами.
Ошибочный номер не удаляет запись; Enter, :b отменяет действие.

Удаление записи и её строк lock_access выполняется в одной транзакции. Перед DELETE
строка блокируется, и ещё раз проверяется ID аккаунта или описание замка. При ошибке,
включая недостаток прав или внешний ключ, вся операция откатывается.
Программа не удаляет logs и id_registry и не сбрасывает AUTO_INCREMENT. Физическая
карта при удалении аккаунта не стирается. Существующие триггеры БД продолжают действовать.

## Смена ID и запись карты

ID на наклейке — main.id, номер в памяти карты — main.card_id.
Пункт 10 вызывает `changeId(cardId, OUT newId, OUT errCode)` после предупреждения.
Выводится **ID ИЗМЕНЕН**, затем новый ID и обязательное подтверждение обновления наклейки.
При ошибке ввода явно сообщается о неправильном ID. Незавершённое подтверждение
сохраняется в pending_id_change.json и восстанавливается после запуска; повторного CALL нет.
Не удаляй журнал до завершения подтверждения. Используй одну копию программы из этой папки.

Пункт 11: приложи одну карту и подтверди запись. В память записывается выбранный card_id;
после успешной проверки обратным чтением выводится напоминание сверить ID на наклейке.
Перед записью библиотека заново опрашивает устройство; отсутствие карты не считается
успехом. После любой попытки фоновый опрос возобновляется, в том числе после ошибки.
Он работает во всех меню, поддерживая штатные цвет и звук; выбор аккаунта по карте
разрешён только в поиске. Дополнительный писк вызывается только после записи, T=10.

Все исправления ввода, опроса и восстановления индикации находятся в коде программы
(modules/card_console.py, modules/windows_console.py), **не в wcopy_reader.py**.
Протокол, ключ, расположение номера и проверка записи остаются библиотечными.
При обрыве БД результат изменения может быть неопределённым; автоматического повтора
INSERT/UPDATE/DELETE/CALL нет. После восстановления связи проверь данные.

## Права БД

Помимо SELECT на main, locks, lock_access и EXECUTE на setLockAccess/changeId, нужны:

- INSERT и DELETE на main — создание/удаление аккаунтов;
- UPDATE колонок name, money, losa, netrunner_lvl, police, password таблицы main;
- UPDATE(description) и DELETE на locks — новые действия с замками;
- DELETE на lock_access — очистка прав при удалении аккаунта/замка.

Прямой UPDATE main.id или main.card_id не используется. `police` и `joinrpg_id` должны допускать NULL.
Программа не меняет привилегии и не выполняет миграций автоматически.
Если у прежнего master отсутствуют новые права, их должен добавить администратор БД.
Для атомарных операций таблицы и затрагиваемые триггерами таблицы должны быть транзакционными
(InnoDB). История действий самостоятельно не добавляется в logs, работают существующие триггеры.

## Проверки

Из папки `cyberwall_master_manager`:

```powershell
py -3 -m unittest discover -s tests -v
```

Для полного набора тестов настрой путь к библиотеке и размести её из отдельного
репозитория, как описано выше. Некоторые тесты подменяют её функции, поэтому сам
модуль `wcopy_reader.py` должен быть доступен, хотя физический USB-считыватель не нужен.

129 автоматических проверок используют имитации MySQL/USB: ввод, поиск по карте,
фоновые опросы, восстановление после ошибки записи, создание/удаление, SQL-параметры,
откаты, конкурентные изменения и состав ZIP. Сервер MySQL для этих проверок не нужен.
`start.bat` не запускает тесты. `build_release.py` выполняет самопроверку готового EXE;
полный набор unittest дополнительно запускает workflow Manager tests.
Реальные подключения к БД, USB-считыватель и запуск BAT проверяются отдельно на Windows.

Обнови оба репозитория, сохранив собственные параметры `config.toml`. В окружении

### Выбор и восстановление соединения

В общем меню поиска выбери **`:menu` → 4**, затем поиск и устройство из списка.
После успешного подключения его адрес и имя сохраняются в `config.toml` с сохранением
комментариев и остальных настроек. Если записать файл нельзя, подключение остаётся
активным, а программа показывает ошибку сохранения. Другой термопринтер выбирается
через то же меню; неудачная попытка не заменяет последнее успешное устройство.

При запуске программа подключается к последнему устройству в фоне. Соединение
остаётся открытым между отпечатками. По умолчанию проверка связи выполняется каждые
2 секунды, повторное подключение — через 5 секунд после обнаруженной ошибки;
поиск при каждой попытке занимает до 15 секунд плюс время установления соединения.
Фактическое обнаружение обрыва также зависит от Bluetooth и ОС.
Ручное отключение приостанавливает автоподключение до команды «подключиться к
последнему» / выбора устройства либо нового запуска программы.

### Печать

- Меню аккаунта: **13 — печать наклейки ID**, затем **1 — ID и имя** или **2 — только ID**. Берётся актуальный внешний
  `main.id`, а не `card_id`. Имя печатается заглавными; максимум три слова по 11 символов.
- Общее меню: **`:menu` → 3** → с именем / без имени → количество (по умолчанию 1).
  Все экземпляры передаются одной многостраничной серией, без подтверждений между ними.
- `max_copies` ограничивает серию (по умолчанию 100; диапазон 1–100).
- Пока выполняется операция, второе задание не ставится в очередь. При отсутствии
  соединения печать отклоняется. После обрыва вся оставшаяся серия отбрасывается:
  соединение восстанавливается автоматически, задание — никогда.
- «Серия отправлена» означает передачу данных, не подтверждение физического окончания.
  При обрыве часть серии могла напечататься или остаться в буфере устройства.
  Количество уже вышедших наклеек программа не угадывает.

Размер макета 40 × 30 мм, ширина ленты 57 мм и тип бумаги находятся в
`[printer.paper]`; плотность печати — `printer.blackening`, оформление —
`[printer.layout]`. Для пустых бланков направляющие сегментов включены всегда.
После ручного изменения настроек перезапусти программу.

`type = "labels"` допускается только если профиль реализует аппаратное определение
границ. Неподдерживаемый режим выдаёт ошибку до передачи изображения, без подмены
этикеток непрерывной лентой. Калибровка доступна через `:menu` → 4 только при поддержке
профилем; в текущем адаптере подтверждённой команды калибровки ещё нет.

Серия использует темп передачи и протокол TiMini, без искусственного ожидания
«N секунд на один шаблон». Для V5G в закреплённой версии используется ограничение
порций и пауза 30 мс между ними; обработка сигналов паузы есть, но ожидание этих
сигналов в BLE-профиле не включено. Серию из 10 экземпляров и восстановление связи
нужно проверить на физическом термопринтере. Программные тесты заменяют устройство
имитатором и не подтверждают качество печати или работу датчика этикеток.

## Навигация и формат подсказок (2.6.0)

В поиске и меню аккаунта/замка один вход **`:menu`** открывает общее меню:

| Пункт | Действие |
|---|---|
| 1 | Создать аккаунт |
| 2 | Пакетная запись карт: новая работа или продолжение |
| 3 | Печать шаблонов: выбор макета и количества |
| 4 | Термопринтер: выбор, соединение, калибровка |
| 5 | Отключиться от БД |
| 6 | Выйти из программы |
| 0, Enter, :b | Вернуться назад |

В аккаунте **13 — печать наклейки ID** открывает выбор: **1 — ID и имя**,
**2 — только ID**. Печать начинается после выбора макета; отмена ничего не отправляет.

Единый стандарт: **`клавиша — действие`**; равнозначные клавиши перечисляются через
запятую (**`Enter, :b — назад`**), разные действия — через точку с запятой
(**`да — подтвердить; Enter, :b — отмена`**) или отдельными строками.
`/` больше не используется как разделитель действий. Команды `:q` и `:b` остаются
быстрыми выходом и возвратом. В обязательной проверке сменённого ID сохраняется
специальная команда `:disconnect`, чтобы выйти из недоступной БД, не обходя проверку.
